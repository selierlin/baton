# 截图态（框选 + 原地标注）场景测试清单

贴图那份清单（`pin-test-matrix.md`）解决的是「事件送到了谁」；截图态这边同一类问题
更多：选区 8 个手柄、方向键改选区、改完选区图元会不会跟着跑、工具条会不会被顶出屏幕。
`Baton --capture-suite` 按本表逐条跑，输出 `PASS / FAIL`，退出码非 0 表示有回归。

## 怎么跑

```bash
./Scripts/make-app.sh debug
./dist/Baton.app/Contents/MacOS/Baton --capture-suite; echo "exit=$?"
cat /tmp/baton-capture-suite.log
```

- 需要「辅助功能」权限（投递 CGEvent）。跑的时候会铺满屏幕的覆盖层、真的挪鼠标，
  别在演示中途跑。
- **不真抓屏**：终端启动的进程拿不到 `ScreenCaptureKit` 的共享内容
  （`--inplace-probe` 早就撞过 `noDisplays`），套件用一张自绘的假冻结帧铺满主屏。
  覆盖层、手柄、遮罩、原地标注走的仍是线上那条代码路径，只有「抓哪块像素」被换掉。

## 三层验证，各管一段

| 层 | 管什么 | 在哪 |
|---|---|---|
| 单测 | 纯逻辑：选区几何、手柄方向、按键→边、像素偏移 | `swift test`（309 条） |
| 实机场景 | 事件送到谁、画布/工具条/遮罩有没有跟着变 | `--capture-suite`（23 条） |
| 人工 | 会弹模态框、要人眼判断的 | 下表标「人工」 |

## 反向验证记录

证明这些断言能抓到问题——把实现改回旧写法，看对应用例会不会红。

| 临时改动 | 结果 |
|---|---|
| `SelectionGeometry.imageOffset` 正负写反（历史上的「箭头跟着选区跑」） | 只有 C11 红，位移 −40/−40 |
| 覆盖层 `hitTest` 不再把外沿手柄转给画布 | 只有 C05 红（拖完选区没变） |
| `adjustSelection` 不调用 `hostView.updateSelection` | 只有 C06 红（遮罩停在旧选区） |
| 工具条固定放选区下方（去掉上翻） | 只有 C20 红（被夹到屏边） |
| `adjustSelection` 不更新导出用的底图 | 只有 C22 红（导出仍是旧裁剪 692×386，期望 752×426） |

## 两个测量限制

1. **假冻结帧**：套件验的是交互与几何，不验「截出来的像素对不对」。像素那条路由
   `ScreenCapturer` 自己的测试和实机截图覆盖。
2. **只铺主屏**：`OverlayController` 多屏时一屏一个窗口，套件只造主屏的帧。
   多屏的问题（副屏坐标翻转、key window 落在别的屏）目前只能实机看。
