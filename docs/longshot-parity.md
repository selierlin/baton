# Longshot 复刻方案

对照对象：Longshot 1.4.9（`/Applications/Longshot.app`）
对照范围：**截图 → 选区 → 标注 → 输出** 这条主链路
产出日期：2026-10-24

---

## 0. 先说结论

Baton 的标注**图元种类**已经和 Longshot 齐平（矩形、椭圆、直线、平箭头、内凹箭头、画笔、记号笔、
高亮三种、马赛克三种、文本、文本标注、序号、尺子、长度、区域、取色）。真正缺的不是「工具不够」，
而是**围住内容的那块选区不可编辑**：

- Longshot：圈完之后，选区还能拖 8 个点、整块平移、四边外扩/收缩，全用键盘也能微调 1px
- Baton：鼠标一松就锁死进标注，想改只能 Esc 重来

这一条是「手感不对」的主要来源，也是本方案的第一优先级。其余是键位补齐和几个缺口功能。

## 2. 架构差异导致的一个关键取舍

Longshot 的流程是「圈完 → 工具条和选区同时在场 → 随时能改选区」。
Baton 的流程是「mouseUp → 立刻 commit → 铺画布进标注」，画布接管鼠标后选区就不可改了。

要复刻「圈完还能调」，**不能**在画布层改裁剪（那要重抓图、还得平移已画图元，风险极高）。
正确做法是在 `commit` 之前插入一个短命的**待确认态**：

```
mouseDown → drag → mouseUp
                     ├─ 单击过窗口          → 直接 commit（保持现在的快路径）
                     └─ 拖框 → [待确认态]   → 拖手柄/内部/方向键 调整
                                              ├─ 点工具 / 在选区内按下 / ↩ → commit
                                              └─ ⎋ / q → 退出
```

代价：松开鼠标后到「能画」之间多一层状态机。
**要求**：在选区内按下必须**立刻** commit 并把这一下转交给画布，不能有可感知延迟；只有按下位置
落在手柄上才停留。这一条是 P1 的验收硬指标。

## 3. 分期方案

### P1 — 选区可编辑（最高收益，改动量：大）

**做什么**
- 8 个手柄（四角 + 四边中点），命中半径 6pt，光标按方位变 `resizeLeftRight` 等
- 选区内部拖动 = 整块平移，贴边不越屏
- `↑↓←→` 移 1pt；`⌘↑↓←→` 对应边外扩 1pt；`⇧↑↓←→` 对应边收缩 1pt（最小 2×2）
- `q` 取消选区回到无选区态；`⎋` 退出；`⎋` 在待确认态先退到无选区，再按才退程序
- 提示条补 4 行（移动区域、外扩/收缩、取消选区）

**改哪里**
- `OverlayKit.swift`：新增 `SelectionAdjuster`（纯几何，可单测）+ 待确认态；`mouseDown` 优先级
  必须一次写死：**手柄 > 选区内部 > 窗口/元素 > 空白新框**
- `OverlayKit.swift:631 mouseUp`：改为先进待确认态，只有「单击命中窗口」走原快路径
- `ShortcutHintView.swift`：行数从 7 加到 11

**风险**
- `mouseDown` 四层优先级是本方案最容易出错的地方。写之前先把它写成决策表，配 12 个单测覆盖
  「点在角上 / 点在边上 / 点在内部 / 点在选区外空白 / 点在选区外窗口上 / 点在选区内窗口上」
- 窗口拾取（hover 探测）和选区拖动会互相抢事件，必须用「按下时锁定意图」而不是每帧判断

**验收**
- 单测：几何矩阵 12 条（每类命中 + 越界钳制 + 最小尺寸）
- 实机：框一块 → 拖右下角 → 尺寸变化；按 `↑` 20 次 → 选区上移 20pt；`⌘→` 5 次 → 右边扩 5pt
- 实机：在选区内直接按下拖动画箭头 → 不经过停留，直接进入绘制
- 回归：单击窗口截图仍然是一步到位，没有变慢

---

### P2 — 键位与工具组对齐（改动量：小）

**做什么**
- `5` 组补 `labelText`（Longshot 的 5 是标注组，Baton 现在是尺子组）；`7` 组只留 `text`
- 补 `O` 打开、`A` 隔空投送、`R` OCR、`⌘R` OCR 并复制、`⌥Q` QR
- 提示条与 `AnnotateTool.key` 保持单一数据源（现在 hintRows 和 key 是两份）

**不做**
- 不补 `9`/`0`（Longshot 没有，椭圆和箭头归 1/2 组连按）
- 不改 `V` 选择（Baton 的悬停+单击已经比它快）

**验收**
- 单测：遍历 `AnnotateTool.allCases`，断言「每个工具的 key 都能在提示条里找到」
- 实机：`1` 连按 4 次 → 矩形 → 椭圆 → 矩形；`5` 连按 5 次走完标注组一轮

---

### P3 — 区域内回溯 B / ⌘B（改动量：中）

**做什么**
- `CaptureSettings.lastArea` 从单值改成**小栈**（保留 10 条，含 displayID）
- 待确认态按 `B` 跳到上一个区域、`⌘B` 跳下一个；跳到的是「已记录的区域」而非重新截图
- `,` 回溯上一张截图 = 重新载入上一次的图进标注（不重新抓屏）

**风险**
- 跨屏区域（displayID 不同）要重建覆盖层，不能只改 rect，否则坐标全错
- 栈满淘汰要按「最久未用」，不是简单 FIFO

**验收**
- 单测：栈的压入/回溯/淘汰 8 条
- 实机：连截 3 块不同区域 → 进第 4 次框选 → 按 B 三次依次回到前 3 块

---

### P4 — 截图阴影 S（改动量：中，独立一期）

**做什么**
- 窗口截图：把窗口图与投影合成，四周留 padding，透明背景
- 区域截图：矩形投影，可配圆角
- 待确认态按 `S` 切换，提示条显示当前状态

**为什么单列**
- 会改变**输出尺寸**（加 padding），标注坐标、贴图尺寸、保存尺寸全跟着变
- 必须一次性把 `CaptureSelection.rect` 与 `AnnotatedImage` 的坐标基准定清楚，否则每个出口都要补一次

**验收**
- 像素级：同一窗口，Baton 与 Longshot 各截一张，比对 padding 比例与投影模糊半径
- 单测：加阴影后 `rect` 与 `image.size` 的一致性断言

### P5 — 贴图窗口可标注（已完成，改动量：大）

**Longshot 的事实**（`defaults read com.chitaner.Longshot` + `zh-Hans.lproj`）

| 键 | 动作 | 键名 |
|---|---|---|
| `R` | 缩略图模式 | `pinToggleMinHolding` |
| `=` / `-` | 放大 / 缩小 | `pinZoomIn` / `pinZoomOut` |
| `空格` | 显示工具条 | `pinToggleToolbar` |
| `↩` / `⌘D` / `⇧⌘D` | 复制 / 保存 / 保存并复制 | `pinCopy` / `pinDownload` / `pinDownloadAndCopy` |
| `⌘=` / `⌘-` | 不透明度 ± | `pinIncrease/DecreaseWinAlpha` |
| `⌘Z` / `⇧⌘Z` | 撤销 / 重做 | `pinUndo` / `pinRedo` |
| `↑↓←→` | 移动贴图 | `pinMoveMedia*` |
| `Esc` | 退出钉图 | `pinExit` |

关键：那个「工具条」是**标注工具条**。`pasteToolbarItemsRawValue` = 8 组画笔 +
分隔 + `pinUndo`/`pinRedo`/`pinDownload`/`pinCopy`/`pinFinishEdit`，
也就是说 Longshot 的贴图是「可以继续画的便签」，不是只读预览。

**Baton 的实现取舍**

- 画布 `AnnotateCanvasView` 作为贴图视图的子视图，坐标固定为**原图像素**，`drawsBaseImage = false`
  （底图仍由 `PinView` 按窗口设备像素重采样画，比原图直缩清晰）。窗口缩放只改画布的点尺寸，
  标注坐标不动。
- 工具条挂在一条**无边框子面板**（`addChildWindow`）上，浮在贴图窗口外侧；小图上不会盖内容，
  位置跟着 `windowDidMove/Resize` 重排。没有塞进窗口，是因为贴图窗口的 frame 就是图片尺寸，
  而工具条有 500pt 宽。
- 工具条显隐 = 标注态开关：收起时画布 `interactive = false`（`hitTest` 返回 nil），
  拖拽回到「移动窗口」；这也是 Longshot 里空格的意义。
- 画布新增两个宿主接口：`interactive`（只读时穿透事件、`mouseDownCanMoveWindow = true`）
  和 `keyInterceptor`（贴图里 `R` 是缩略图，不能落到画布的 OCR 上）。
- 键位表抽成 `PinShortcuts.action(for:)`，纯函数，不认字符只认 keyCode（⇧ 会把 `=` 变 `+`）。

**已知限制**

- 标注只在窗口存活期间保留，关掉贴图就没了；数据库结构没动。要留下来用 `⌘D` / `↩` 导出。
- `Esc` 定成两段（先退标注、再关贴图），比 Longshot 的「一键退出」温和一点。

**验收**

- 单测 19 条：键位映射 10 条、画布两种态 3 条、真窗口上的空格/R/方向键/Esc 6 条
- 实机：`Baton --pin-probe` 会钉一张测试图并直接进标注态，截屏到 `/tmp/baton-pin.png`

## 5. 防返工机制（针对最近几轮的问题）

最近三轮返工的共性：**先改、再凭肉眼判断、不对再改**（放大镜倍数错了三次，最后靠帧间互相关才定准）。
这次改成：

1. **每期先测量、后实现**。测量结论写进本文档的表格，后续只按数据做，不再边调边猜。
2. **每期只动一个子系统**，独立提交。OverlayKit 的改动不夹带标注层改动。
3. **每项有可执行验收**，不写「看起来对了」。能写成单测的写单测，只能实机的写清具体按键序列和期望数值。
4. **交互冲突先出决策表**。P1 的 `mouseDown` 四层优先级先以表格形式给你过一遍，再写代码。
5. **每期结束同步三处**：`README.md`、本文档的状态列、vault 里的 `Baton-方案设计-v2.1.md`。
